# Webmotion source strategy

Choose sources by the material needed, never by a permanent hierarchy. Recheck access, filters, limits, pricing, and platform capabilities during the task because they change.

## Contents

1. Collection routes
2. Sources by function
3. Platform-specific moves
4. Selection recipes

## Collection routes

Use the cheapest route that returns inspectable material:

1. **Available MCP:** search, retrieve, or install through a connector already exposed in the harness.
2. **Existing CLI:** use an installed, authenticated official CLI when it is safer or faster than clicking.
3. **Browser or Computer Use:** search visually, filter, preview, open detail pages, copy prompts/code, and download accessible assets.
4. **Manual assisted navigation:** tell the user exactly what to open or select only when interaction or authentication requires them.
5. **Reconstruction:** capture and rebuild the rendered interaction when code or assets cannot be acquired.

Do not install a connector, start a paid plan, or bypass authentication without matching authorization merely to avoid a viable fallback. Use task-relevant credentials already configured. If budget is unknown, start with accessible free material and mention a paid alternative only when it is materially better.

### Technical truth

Use official Motion, GSAP, Three.js/R3F, Rive, Lottie, MDN, CSSWG, browser-engine, accessibility, and performance documentation to confirm APIs and support. A gallery can set the bar; a live prototype and primary docs confirm feasibility.

## Platform-specific moves

### 21st.dev

1. Search visually for the required component, interaction, theme, template, or SVG.
2. Open promising cards and inspect preview, variants, dependencies, and code.
3. Use **Copy prompt** when an agent-ready recipe is the fastest route; use **Copy code** or the install command when direct integration is better.
4. If the 21st MCP is already exposed, use it to search and retrieve. The current official endpoint is `https://21st.dev/api/mcp`; recheck the official setup page before configuring it.
5. If the official CLI is installed and authenticated, begin with `21st search "<need>"`, inspect the result, then use the current `21st add <component>` or retrieval command confirmed by `21st --help`.
6. Otherwise use Browser or Computer Use. Do not block free exploration on a professional account.
7. Recheck current free limits and paid capabilities at task time.

### MotionSites

1. Choose the useful surface: sites, apps, sections, or backgrounds.
2. Filter free or premium according to known access; default to accessible material when budget is unknown.
3. Open a detail view and copy the useful prompt, background URL, or offered asset.
4. Decompose the recipe into composition, material, camera, interaction, and technique, then adapt what the project needs.

### Visual galleries and authored sites

- Use the gallery to discover; open the live experience when temporal behavior matters.
- Capture only the sequence needed to understand or reconstruct the mechanism.
- When the live site is gone, use an available recording or still as partial evidence and prototype the missing behavior.

### Asset libraries

- Preview the actual file in context before collecting many alternatives.
- Prefer editable formats when the direction requires color, timing, or state changes.
- Generate a custom asset when a marketplace result weakens the composition.
- For still-image generation, provider routing, dependency installation, or transparent cutouts, follow [asset-acquisition.md](asset-acquisition.md).

## Selection recipes

### Component or interaction

Try 21st.dev, Kinetics, Magic UI, BuouUI, Motion, or GSAP according to stack and desired behavior. Collect a prompt, code, or component, integrate it, then tune it against the project motion system.

### Animated background or visual substrate

Compare MotionSites, Videezy, generated media, the Jakub Antalik experiments, River, and Three.js/shader examples. Choose based on material fit, editability, performance, and the desired response to input.

### Marketing or portfolio direction

Combine one quality-bar source, one implementation source, and one reusable component or asset source. No named platform is mandatory.

### Immersive 3D

Start from a live authored experience or material experiment, prove the expensive primitive with Three.js/R3F, and prototype it on a representative mobile target before expanding the scene.

### Video or vector asset

Search the relevant asset library, test the real file or a faithful proxy in the composition, and replace it with generated or procedural material when the available stock feels generic.
