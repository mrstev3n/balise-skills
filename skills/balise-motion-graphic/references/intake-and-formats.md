# Intake and formats

Use this reference to turn an incomplete request into a bounded motion-graphics brief without imposing a questionnaire.

## Intake order

1. Inspect the request, project, identity, assets, sources, prior decisions, and target channel.
2. Extract known facts before asking anything.
3. Ask about the objective and distribution context only if they cannot be inferred.
4. Ask further questions only when the answer changes the narrative, rights, cost, or feasibility.
5. State reversible assumptions and continue when details are non-blocking.

## Decisions to capture

| Decision | Evidence or question | Expected recommendation |
| --- | --- | --- |
| Purpose | Teaser, announcement, launch, explainer, identity, title sequence, loop, event video? | Narrative structure and success condition |
| Audience | Who watches, where, and what should change afterward? | Message hierarchy and tone |
| Channel | Feed, story, presentation, event screen, site embed, broadcast? | Ratio, safe zones, text scale, silent-first behavior |
| Duration | Imposed or open? How many indispensable messages? | Duration range and content cuts |
| Sound | Music, voice, SFX, silence? Is audio likely to be heard? | Cue strategy, captions, silent version |
| Identity | Guidelines, typography, palette, motifs, assets, references, anti-references? | Audit before visual production |
| Facts | Names, dates, places, claims, CTA, language, spelling? | Locked factual sheet before storyboard |
| Output | Engine, codecs, resolutions, frame rate, variants, deadline, handoff? | Production and validation plan |
| Rights | Asset, music, font, logo, likeness, and source permissions? | Blockers and delivery conditions for material actually used |

Objective or channel truly unknown normally blocks format-dependent production because either can change every downstream decision. For a deliberately exploratory request, a ratio-neutral hero frame may proceed under an explicit hypothesis; do not present it as the approved production format. A missing decorative preference is not blocking. When facts conflict, verify them from an authoritative source or ask the user; never animate the ambiguity.

## Starting duration ranges

| Type | Starting range | Probable structure | Main risk |
| --- | --- | --- | --- |
| Signature loop | 3–6 s | One gesture, impact, return | Overloading a tiny loop with narrative |
| Micro-teaser | 6–15 s | Hook, tension, name or date | Turning it into an explainer |
| Social launch | 15–30 s | Promise, proof, benefit, signature | Feature accumulation |
| Short explainer | 30–60 s | Problem, mechanism, outcome, CTA | UI tour without value narrative |
| Deep explainer | 60–90 s | Full arc, proof, respiration | One unchanging tempo |
| Case film | 60–180 s | Context, idea, system, applications, impact | Confusing length with depth |

Treat these as hypotheses. Reading time, voice-over, language, audience, number of scenes, and platform behavior can justify a different duration.

## Format guidance

- Derive the master ratio from the primary channel, not from a tentative user guess.
- Define safe zones and secondary crops before composing.
- Favor large type and fewer messages for mobile feeds.
- Design for comprehension without audio when silent autoplay is likely.
- Preserve a clean master and derive variants rather than squeezing one composition into incompatible ratios.
- Test extreme copy, long names, accents, dates, and localized text before locking the system.
- Choose frame rate from source cadence, delivery requirements, motion language, and render cost; do not equate 24 fps with quality or 60 fps with modernity.
- Keep stable master ratio families, but recheck volatile platform limits and UI overlays from official sources at task time.
- Read [export-and-codecs.md](export-and-codecs.md) for frame-rate starting points, master families, codecs, and proof commands.

## Minimum response for a vague brief

Return:

1. the interpreted purpose and audience;
2. up to three blocking questions at most;
3. explicit working assumptions;
4. recommended channel format, duration, sound posture, and message structure;
5. the first inexpensive validation gate.

Do not begin full production from “make it premium” or “make it dynamic.” Convert those adjectives into an observable direction first.
